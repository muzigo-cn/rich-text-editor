# 富文本编辑器独立项目提取计划

## 一、目标与决策(已确认)

| 维度 | 决策 |
| --- | --- |
| 目标形态 | Monorepo(可发布 core 库 + react 适配包 + demo 演示站) |
| 提取范围 | 话题(#)插入 + 图片/视频图文混排 + 选区/光标/跨端/输入法/字符计算(全部) |
| 原生耦合 | JSBridge/原生上传抽象为可注入接口(`PlatformAdapter`),默认提供纯 Web 实现 |
| 技术栈 | 核心框架无关(vanilla TS core + React 适配层;Vue 适配层列为二期) |

### 2.2 需抽象/替换的 App 耦合

| 依赖 | 耦合点 | 处理 |
| --- | --- | --- |
| `autoFocusBridge` / `scrollEnabledBridge` | focus/blur 调原生键盘与滚动 | 抽象为 `PlatformAdapter.onFocus()/setScrollEnabled()` 接口,默认 Web 实现(浏览器原生 focus) |
| `showPhotoViewerBridge` | 图片预览调原生 | 抽象为 `PlatformAdapter.previewMedia()`,默认用浏览器预览 |
| `NativeUpload` / `NativeVideo` 上传 | 原生上传流程 | 抽象为 `MediaUploader` 接口,默认 Web 用 `input[type=file]` + 模拟上传状态 |
| `getDom`(imp-h5) | DOM API shim | 直接用 `document`,移除 shim |
| `@pui` `View` | React 组件 | core 不用;react 适配层用原生 `div` |
| `detectMobileOperatingSystem` | iOS/Android 分支 | 保留为 core 内 portable util(基于 UA),或注入 `PlatformAdapter.getOS()` |
| `wpx2vw2` | px→vw 响应式 | 迁为 core 内轻量 util,或改用纯 CSS(rem/vw) |
| `getUrlParams` | URL 取参 | demo 侧处理,不进 core |
| `classnames` | 类名拼接 | react 适配层保留;core 用模板字符串 |
| `ReactDOM.render`(上传态) | React 渲染上传中/成功 | core 用回调 + 占位节点;react 适配层注入 `UploadLoading/Success/Failure` 组件 |

### 2.3 样式与主题

源 SCSS 依赖全局 CSS 变量:`--text-disabled`、`--Text-text-primary`、`--text-link`。提取为 core 的 `theme.css`,提供默认值并允许覆盖:
```css
:root {
  --rte-text-primary: #000;
  --rte-text-disabled: #949598;
  --rte-text-link: #2762EC;   /* 话题高亮 */
  --rte-placeholder: ...;
}
```
`.topicHightColor` / `.insertImg` / `.insertVideo` / `.insertImgBox` / `.insertDivZwBr` 布局样式迁入 core 样式表。

## 四、核心抽象接口设计

```ts
// core/src/platform.ts
export interface PlatformAdapter {
  getOS(): 'iOS' | 'Android' | 'Other'
  onFocus?(root: HTMLElement): void            // 默认: root.focus(); App: autoFocusBridge()
  setScrollEnabled?(enabled: boolean): void   // App: scrollEnabledBridge; Web: no-op 或锁滚动
  previewMedia?(src: string): void            // 图片预览
}

// core/src/types.ts
export interface MediaUploader {
  upload(file: File | MediaFile, onStatus: (s: UploadStatus, url?: string) => void): void
  // 默认 Web 实现:input[type=file] + setTimeout 模拟 loading→success
}

export interface EditorOptions {
  root: HTMLElement
  maxLength?: number                                  // 默认 180
  platform?: Partial<PlatformAdapter>                 // 注入原生能力
  mediaUploader?: MediaUploader
  placeholder?: { focus?: string; blur?: string }
  onChange?: (html: string, plain: string, length: number) => void
  onTopicTrigger?: () => void                         // 输入 # 时回调(由宿主弹出话题面板)
  onMediaRequest?: (type: 'image' | 'video') => void
  onLengthLimit?: (isOver: boolean) => void
}
```

core 对外暴露 `createRichTextEditor(options)` 返回 `{ insertTopic, insertMedia, getHTML, getLength, destroy, focus }` 等方法;react 包用 `useRichTextEditor` 桥接。

## 五、分阶段实施步骤

### 阶段 0:脚手架与依赖清单(产出:可运行空工程)
- 初始化 pnpm monorepo、tsconfig.base、workspace 配置
- 建立 `packages/core`、`packages/react`、`apps/demo` 三个包骨架
- 配置构建(core 用 tsup 输出 ESM+d.ts;demo 用 Vite)

### 阶段 1:core 核心迁移(产出:框架无关编辑器内核)
- 按 §2.1 把 community.ts 的纯函数迁入对应子模块,逐个替换 `getDom`→`document`、`detectMobileOperatingSystem`→注入
- 实现 `editor.ts`:挂载 contentEditable root、绑定 onInput/onFocus/onBlur/onKeyDown/onCompositionStart/End、`selectionchange` 监听
- 实现 `event.ts`:把 RichTextarea 的 `handleDivChange` 逻辑搬入(删除/输入/IME/# 检测/样式继承治理)
- 实现 `topic.ts` / `media.ts`:insertTopic / insertFile / 删除保护 / 占位节点
- 抽象 `PlatformAdapter` + `WebPlatform` 默认实现
- 迁移样式 SCSS→`editor.css`,补主题 var 默认值
- 编写纯函数单元测试(pointLength/computedLength/countBr/isInTopic 边界)

### 阶段 2:React 适配层(产出:`@rte/react` 可用组件)
- `useRichTextEditor` hook:创建/销毁 core 实例,转发 props→options、回调→props
- `RichTextEditor.tsx`:渲染 contentEditable div、forwardRef 暴露 insertTopic/insertMedia
- `UploadStatus.tsx`:上传中/成功/失败三种态渲染(对应原 UploadLoading/Success/Failure)
- 接入 classNames、主题样式导入

### 阶段 3:Demo 演示站(产出:可在线演示话题+图文混排)
- 话题面板 TopicPicker(模拟数据)
- WebMediaUploader:input[type=file] + 模拟上传生命周期
- 展示:输入 # 弹话题、插入高亮话题、删除话题样式不串、插入图片/视频、媒体后继续输入、字数限制、emoji 计数、iOS/Android UA 切换演示

### 阶段 4:打磨与发布(产出:可发布包 + README)
- core/react 包 `exports`、`types`、`sideEffects`、`peerDeps` 配置
- README(特性、安装、API、Demo 截图)
- 二期:Vue 适配层(可选)

## 六、风险与决策点

1. **`contentEditable` 的 Selection/Range 行为依赖真实浏览器环境**——单测只能覆盖纯函数(pointLength/computedLength),事件流与选区逻辑需靠 demo 端到端验证。建议阶段 1 结束即接 demo 做手测。
2. **iOS 键盘动画 700ms 延迟**等时序补丁属经验值,迁移后需在真机/模拟器回归。
3. **媒体上传状态实时回刷**原用 `ReactDOM.render` 原地更新;core 框架无关后改为「节点 data + 回调」,react 适配层负责渲染。需保证上传完成时 DOM 节点未被删除。
4. **Vue 适配层列为二期**,先保证 core + react 跑通,避免范围蔓延。
5. **wpx2vw2** 可保留为 core util,或 demo 直接用 vw/rem,core 不强制响应式单位。

## 七、范围边界(明确不做)
- 不迁移草稿恢复的持久化逻辑(属宿主业务,core 仅暴露 getHTML)
- 不迁移动态发布的图片拖拽排序(ImgDrag,属宿主)
- 不实现服务端,纯前端库 + demo
- 二期前不做 Vue 适配层
